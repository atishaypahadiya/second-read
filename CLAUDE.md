# Second Read — CLAUDE.md

> Formerly **Sponsor Skipper**. Display name "Second Read" (lowercase `second read` in the UI, see DESIGN.md).
> Identifiers: `second-read`, `SecondRead`, CSS/variable prefix `sr-` / `--sr-`, env vars `SR_*` (the old `SS_*`
> still work), log prefix `[SecondRead]`, LaunchAgent `com.second-read.server`. The word "sponsor" now only names
> the ad category.

Chrome extension that skips **scripted YouTube sponsor reads** and lets **integrated sponsors**
(the creator actually using the product inside the content) play. Local-first prototype:
everything runs on Atishay's M4 Pro MacBook.

## Hard constraints (do not change without asking)

- **Text only.** The transcript comes from YouTube's own caption track, read inside the page.
  No audio download, no Whisper, no yt-dlp.
- **No external datasets.** No SponsorBlock, no third-party APIs.
- **Local LLM only.** Qwen 14B (`qwen3:14b`) via Ollama at `http://localhost:11434` for everything; optional
  `nomic-embed-text` for topic-fit embeddings. No API keys.
  (`SR_DETECT_MODEL=qwen3:8b` can run pass-1 on a smaller model, but both models then stay loaded, ~18 GB, which
  thrashed and timed out on this 24 GB Mac. Only for ≥ 32 GB machines.)
- **Server is stdlib Python.** No pip dependencies unless asked. `server/stats.py` (SQLite via `sqlite3`) holds
  the local stats store, brand normalization, metrics and the dashboard page.
- **Extension is plain Manifest V3 JavaScript.** No bundler, no TypeScript, no npm for now. Icons are generated by
  `scripts/make_icons.py` (stdlib PNG writer).
- **Bias toward playing.** A wrong skip (skipping real content) is the worst failure. When unsure, don't skip.

## How we work

- Build **one build stage at a time** (list below). Don't start the next stage until the
  current one's "done when" check passes on a real video.
- Keep each stage's change small and reviewable. Explain what you changed and how to test it.
- After a stage passes: tick it in the checklist at the bottom and commit
  (`stage N: <summary>`).
- **Before every commit run `python3 scripts/regress.py`.** It replays `server/testset.json` from cached transcripts
  and cached model outputs (zero Ollama calls when versions match), checks expected segments within ±1.5s, asserts
  must-not-skip videos have no skips and forbidden ranges stay empty, and prints a pass/fail table. After a prompt
  change the stored outputs are outdated: run it once with `--allow-model`.
  **It is isolated:** `SR_DATA_DIR` is set to a fresh temp dir before the server is imported, the test-set videos'
  cache files are copied in, and nothing is written back to `server/cache/` (it used to overwrite those files,
  including their stored description). Model outputs it computes with `--allow-model` are kept in
  `server/testset.calls.local.json` (gitignored) and merged into the copies on the next run.
- If a decision in "Open decisions" comes up, ask; don't pick silently.

## The pipeline

```
[1] content.js   video opens / YouTube in-app navigation → video ID
[2] page.js      player.getPlayerResponse() → caption tracks → caption text
[3] page.js      json3 cues → merged lines {start, end, text}
[4] content.js → background.js → POST localhost:8765/analyze
[5] server.py    transcript hash → cache hit? return it
[6] server.py    pass 1: Qwen 14B over windows (first 4 min first) → candidate line ranges
                 pass 2: per sponsor candidate, re-ask with ±90s context → full extent; then pick first/last ad word
[7] server.py    words → seconds (end − 0.3s), skip/keep/show, merge overlaps, cache
[8] content.js   polls GET /analyze every 2s → markers on the progress bar
[9] content.js   playback enters a skip segment → seek to its end → toast with Undo
```

### [1] Video detection (content.js)
- YouTube is a SPA: listen for `yt-navigate-finish` on `document` (plus `popstate`, plus an initial run).
- Video ID = `v` URL param on `/watch`. Ignore Shorts and non-watch pages.
- On every new video: tear down the previous state (listeners, timers, markers, toast). Nothing leaks across videos.

### [2] Caption fetch (page.js, MAIN world)
- Must run in the MAIN world (`"world": "MAIN"` in the manifest) at `document_start`.
- Get the player response from `document.getElementById('movie_player').getPlayerResponse()`.
  **Not** `window.ytInitialPlayerResponse`, which is stale after in-app navigation.
  Wait until `videoDetails.videoId` matches the requested ID.
- Tracks: `captions.playerCaptionsTracklistRenderer.captionTracks`.
  Pick: manual track in the spoken language (= the `asr` track's languageCode) > `asr` (auto) > any manual > first.
- **Path A:** fetch `baseUrl` with `fmt=json3`, `credentials: 'include'`.
- **Path B (fallback when A returns an empty body):** YouTube may require a proof-of-origin token that only the
  player attaches. Patch `fetch` and `XMLHttpRequest` at document_start to capture responses to `/api/timedtext`;
  click `.ytp-subtitles-button` on, wait (≤8s) for the captured response for this video ID, click it back off if it was off.
  If the captured body isn't json3, refetch the captured URL with `fmt=json3`.
- No tracks → report `no captions`; the extension does nothing for that video.
- Talks to content.js via `window.postMessage` (`source: 'sr-content'` → `source: 'sr-page'`).

### [3] Parse (page.js)
- json3 `events[]`: `tStartMs`, `dDurationMs`, `segs[].utf8`. Skip events without `segs` or with whitespace-only text.
- Merge cues into lines: close a line at sentence-ending punctuation or when it would exceed ~8s.
- Keep word timing: `segs[].tOffsetMs` relative to `tStartMs`; word end = next word's start. A seg without
  `tOffsetMs` (manual tracks, and some auto tracks: one multi-word seg per cue) has its words spread by character
  position, **inside `[cue start, next cue start)`**: auto cues stay on screen while the next one is spoken, so
  cue ends are clamped first and the words are placed afterwards. Such lines are `timed: false` (an estimate).
- Output: `[{start, end, text, words: [[start, end, word], …]}]` in seconds, 2 decimals.

### [4] Handoff
- content.js → `chrome.runtime.sendMessage` → background.js → `fetch('http://127.0.0.1:8765/...')`.
- **One payload, forwarded untouched.** `analyzePayload()` in content.js builds the whole POST body (videoId, lang,
  lines, title, creator, channelId, kind, description, paidPromotion, heat, duration, position, analysisLines,
  analysisLang, client builds). background.js sends `msg.payload` as is and only stamps its own build. Never re-list
  fields in background.js: that is how `channelId` and `duration` were silently dropped.
- **Settings do not survive a new extension ID.** `chrome.storage` belongs to the extension ID, and an unpacked
  extension's ID is derived from its folder path, so renaming or moving the folder starts from defaults (settings,
  don't-skip list, popup stats; the server's stats DB is unaffected). A server-side snapshot + restore was built and
  removed again: a new install has no secret to prove it is the same extension, so any extension could read or
  plant snapshots. Storage keys: `settings`, `stats`.
- **Build stamps.** `BUILD` in page.js, content.js, background.js and `CLIENT_BUILD` in server.py are the same number;
  bump all four together when the extension↔server contract changes. The server logs the three it received and warns
  when they differ (a half-reloaded extension).
- **Presence logging (lengths only).** page.js, content.js (dev mode), the service worker console and the server each
  log which metadata fields they hold. Server: `[id] meta (lengths): client=[…] title=… creator=… …` plus
  `WARNING: metadata missing: …` when something that should always be there is not.
- `scripts/wiring_test.js` runs the real content.js and background.js against stubs and checks the POST body
  (and, statically, that page.js replies with everything content.js reads and that the server reads nothing the
  extension doesn't send). `scripts/regress.py` runs it first.
- Reason: content scripts can't call localhost (cross-origin + private network access). `host_permissions` covers the worker.

### [5]–[7] Server (server.py)
API:
| Method | Path | Body / query | Returns |
| --- | --- | --- | --- |
| POST | `/analyze` | `{videoId, lang, title, creator, kind, description, position, lines, analysisLines?, analysisLang?}` | job; starts/resumes it if new |
| GET | `/analyze?v=ID` | — | job `{status, segments, paused?, progress?, cached?}` or 404 `unknown` |
| GET | `/health` | — | `{ok, model, ollama, loaded}` |
| POST | `/feedback` | `{videoId, kind: false_skip\|missed_ad, playhead, segment?, channelId, channelName, title}` | `{ok}`; appended to `server/cache/feedback.local.jsonl` with the cached segment's evidence/reason and pipeline versions |
| GET | `/feedback` | — | `{count, recent}` |

`python3 server/server.py --feedback-report` prints a summary table of the feedback file for tuning sessions.
A `false_skip` without a valid segment, or any report without a playhead, is rejected with 400; the client sends
the whole segment (times, brand, canonical brand, evidence, reason, source) plus the pre-skip playhead, and the
server adds the cached pipeline context and versions. Rows that predate validation are ignored by the report.
**Tests never write to `server/cache/`**: set `SR_DATA_DIR` before importing the server, as `scripts/regress.py` does.

### Stats (server/stats.py, `server/cache/stats.local.db`, gitignored)
- Tables: `videos` (id, channel, title, lang, duration, versions, hints), `segments` (every final segment with
  `brand_raw` as the model spelled it and canonical `brand`), `events` (ts, kind, video, channel, segment times,
  playhead, saved seconds; kinds: skip, undo, seek_into, false_skip, missed_ad, allowlisted), `brand_aliases`.
  **User-agnostic**: no user identity in any row, so rows can later be pooled across users.
- At startup the server repairs rows written by older builds (idempotent): a missing `duration_s` is filled from the
  cached transcript's end, a missing channel from the video's own events, and disclosure columns recorded as 0
  before the tri-state rule are reset to NULL. The position histogram only bins ads whose video length is known
  and says how many it could not place.
- Segment ids are stable across re-records (upsert on video + start + end), so stats are synced on every finished
  job, on cache hits, and when metadata arrives later, without orphaning ad metrics or analyses. `duration_s` falls
  back to the end of the transcript when the client sent none. Segments carry `brand_canonical` for the toast/tooltip.
- Brand normalization order: alias table → fuzzy match against the brands *written* on the description's sponsor
  lines (≥ 0.55, e.g. "Udo" → Odoo) → the single written brand if there is only one (sponsor segments) → fuzzy
  against brands already in the DB (≥ 0.8) → raw spelling. Learned aliases are stored with how they were made.
  **The spoken name beats a domain label:** a sponsor link names the brand only when the model gave none and the
  description wrote none, and then without affixes and TLDs (`headspace-web.app` → Headspace). **A link corrects
  a close match only:** a sponsor's spoken or written name whose letters are ≥ 0.75 alike with the link's name, or
  that sounds the same (vowel-blind key: "Udo"/"Udu" ↔ odoo), takes the link's spelling for that video (never
  learned as an alias); a name that differs substantially is left alone. Rule segments
  (recap, outro, intro, interaction) never get a brand; a non-sponsor segment never borrows the video's hint.
  **Generic words are never a brand** (`GENERIC_WORDS`: tech, pro, plan, sound, …): as a hint they are ignored, and
  as the model's brand they count as "no name". **An alias is learned** only when neither side is generic, the
  spelling has ≥ 4 characters, and the brand is written on a sponsor line or said in the ad's evidence quote; each
  one is logged (`stats: alias learned: …`). Anything else is resolved per video and not remembered.
  `BRAND_RULES_VERSION` (SQLite `user_version`): when the rules change, stored brands are re-derived once at
  startup, learned aliases are dropped and re-learned, and events and codes follow their segment.
- `GET /stats.json` computes: per category (segments, videos, avg/total length, skips, undo/seek-in), per brand (spots, creators, read/integration %, skips, seconds skipped, avg length,
  watch-through = undo + seek-into ÷ skips, wrong-skip flags, top creators, templated one-line verdict), per creator
  (ad density s/min, integration %, brands), overall (time saved, ads per video, % videos with a sponsor, 10-bin
  ad-position histogram), Hall of shame (skip rate × avg read length) and Hall of fame (integration % /
  watch-through / never skipped). A brand is ranked only from `HALL_MIN_SPOTS` = 3 spots.
- `GET /dashboard` is one HTML page with tabs Stats (`/stats.json`), Ad cards and Insights (`/ads.json`), built
  from the design system: the server serves `extension/ui/` at `/ui/` (tokens, components, fonts; a fixed
  whitelist of names). Linked from the popup footer. `?theme=light|dark` forces a theme.

### Ad intelligence (server/intel.py; never blocks skipping)
- **Tier 1**, deterministic, computed right after a job's segments are recorded, stored in `ad_metrics`:
  position % of the video, seconds after the 60s hook, chapter + at-boundary/mid-chapter (chapter times parsed
  from the description), distance to the next "most replayed" peak and whether the ad precedes a top-3 peak (page.js
  samples the player's `.ytp-heat-map-path` SVG into 100 columns), segue type (hard cut / topical bridge / humor
  fake-out / none, from rules on the ad's first sentence and the preceding 30s), reading pace vs the creator's
  median outside ads, CTA count and offers (regex), template similarity (5-word shingle Jaccard vs the same brand's
  ads by other creators; ≥ 0.7 = "template script"), topic fit (cosine of `nomic-embed-text` embeddings, ad vs rest
  of video; skipped if the model isn't pulled).
- **Tier 2**, Qwen, `ANALYSIS_VERSION`, stored in `ad_analysis`: runs only when the worker is idle (no job being
  polled), one segment per idle step, and is **preemptible**: the call is streamed over a raw `http.client`
  connection and a watchdog shuts the socket down the moment a watched job is waiting (≈0.2s; closing the response
  object from another thread does not unblock a read that is waiting for the first token). A preempted analysis
  records nothing and is retried when idle. Per segment: persuasion tags with verbatim quotes (a quote must be in the ad, matched like evidence: normalized,
  whole quote or a run of ≥ 6 words; the log says how many the model returned and which were dropped),
  structure beats, and a better-placement suggestion (timestamp, reason, verbatim quote, flagged if not verbatim).
- Dashboard "Ad cards": mini timeline (ad, chapters, heat, peaks), all metrics, tags, suggestion. "Insights":
  aggregates and distributions across all ads.
- **Promo code vault** (`codes` table, `GET /codes.json?q=`, popup "Codes" tab with search + copy): every code,
  link and offer from the description hints and from each sponsor read's text (incl. spoken "fern dot deals slash
  coddy"), per brand, with the video and the ad's timestamp. **A code must look like one:** 3–20 letters/digits with
  at least one letter, and a digit ("fern20") or ALL CAPS ("HARRIS", only where the text has lowercase at all),
  and never a common word ("QR code that's on screen", "USE CODE BELOW"). The same rule filters description codes,
  which are hint terms. Rows that can never have been a code are dropped from the vault at startup.
- **Disclosure check (fails safe):** two tri-state signals: YouTube's "Includes paid promotion" flag
  (`paidContentOverlay` in the player response; `null` when the client didn't report it) and an (ad)/sponsor/partner
  line in the description (`null` when no description was received; a denial such as "this video is not sponsored"
  is not an ad line). Each sponsor read gets
  `disclosure: disclosed | undisclosed | unknown`: disclosed if either signal is positive, **undisclosed only when
  both are known and negative**, otherwise unknown. `undisclosed: true` is set only in that one case. Stats count and
  the dashboard flag follow the same rule; unknown shows as a neutral "disclosure unknown" pill.

Status values: `queued → classifying → done` (or `error`); `paused: true` while the video isn't being polled.
Every GET/POST for a video counts as a poll.

- Validate video ID (`^[A-Za-z0-9_-]{11}$`), clean lines, sort by start.
- Cache key: videoId + short SHA-1 of `start|text` lines. Cache file `cache/<videoId>.json` holds hash, lang,
  title, model, `versions` {detect, refine, post}, the final segments, the transcript, and `calls`: every raw
  model output keyed by its inputs (`detect|first|last|…`, `refine|…`, `words|…`) with the version it was made
  under. A changed caption track = new hash = everything re-runs.
  **Staged versions** — bump the one(s) a change affects:
  - `DETECT_VERSION`: pass-1 rubric (`SYSTEM_PROMPT`), `OUTPUT_SCHEMA`, window size/overlap;
  - `REFINE_VERSION`: `SYSTEM_PROMPT`, `REFINE_INSTRUCTIONS`, `OUTPUT_SCHEMA` anchors, context size,
    `WORD_PROMPT`/`WORD_SCHEMA`;
  - `POST_VERSION`: evidence gate, thresholds, snapping, merge, filters (no model calls; re-process is < 1s).
  A rubric change in `SYSTEM_PROMPT` affects both passes: bump DETECT and REFINE.
  **Inputs digest:** besides the transcript hash, a job/cache entry carries `inputs` = hash of (transcript, title,
  description, paid-promotion flag, analysis track, word timings; the transcript hash itself only covers line
  starts and text, so better word estimates from a newer page.js redo the cuts without any model call). A request with a different digest for the same transcript is
  re-processed (model calls reused where their own inputs are unchanged), so a job created without metadata can
  never mask a later request that has it. Metadata that doesn't change the analysis (creator, channelId, kind,
  duration, heat) is filled into the existing job and synced to stats instead. The cache file also stores the
  request `meta` (incl. the description) so a video can be replayed exactly. The server logs how many
  model calls were reused vs computed. A POST with a new hash while a job is running supersedes it; the old
  thread's result is discarded.
- Access: Host must be localhost/127.0.0.1 (DNS rebinding), http(s) Origins are refused, and
  `SR_EXTENSION_ID=<id>` restricts extension Origins to that one extension (other extensions get 403). A request
  with no `Origin` header is still answered (curl, the dashboard page). `scripts/install.sh` sets the variable in
  the LaunchAgent from `.env`.
- **Scheduler:** one worker thread, one Ollama call at a time, always for the most recently polled job. A job
  not polled for 10s is paused between calls (partial model outputs are on disk; it resumes when polled again).
  At most 4 unfinished jobs in memory; beyond that the least-recently-polled one is evicted, never the newest.
- **Windows:** 240s with 30s overlap. **Prefilter:** a window is sent to the model only if its text contains a
  sponsor cue (sponsor, brought to you, thanks to, special thanks to, use code, promo code, discount, % off, link in
  the description, .com/, check out, sign up, free trial, partnered with, in partnership with, supported by, made
  possible by, today's sponsor, head to, go to, visit, …) or a description hint. A skipped window that still names a
  description-hint brand is logged as `POSSIBLE MISS`. A second cue list (patreon, membership, merch, my course,
  giveaway, donate, charity, affiliate, my other video, …) also sends windows for the non-sponsor categories. Skipped windows could never yield a skip (the
  evidence gate needs a verbatim cue). Log: `prefilter: X of Y windows sent`.
- **Order:** the window containing the playhead first, then later windows, then earlier ones; within each group,
  windows matching description hints first. Segments are published after every window.
- **Description hints:** brands (capitalized words on "(ad)"/sponsor lines), promo codes, sponsor links and chapter
  titles are extracted from the description, added to the cue list, used for ordering, and shown to the model in the
  prompt header (so a misheard "Udo" can be matched to Odoo). **Only sponsor lines contribute links and brands:** a
  line with an (ad)/sponsor/partner marker, a promo code or an offer, or the line right after one. The creator's own
  shop, socials (with or without `www.`) and source links are ignored, and any term that is really the creator's own
  name ("fern" from fern.deals/coddy, "HARRIS" for Johnny Harris) is dropped from the hint terms. Generic capitalized
  words on a sponsor line ("Coddy Pro Plan for Tech lovers" → only Coddy; `stats.GENERIC_WORDS`) are not brands either. Reason: hint terms
  count as sponsor cues for the skip gate, so they must never include things the creator says in ordinary content.
- **Chapter fast path:** a description chapter whose title reads like an ad (sponsor, ad, advert, promo, partner,
  paid promotion, and common non-English equivalents) ≤ 4 min long becomes a `skip` segment from its bounds
  immediately, snapped to pauses but never past the chapter end, `source: chapter`, no model call; the evidence is
  the chapter title. Detect windows it covers are deferred like hint regions. **Trade-off:** this trusts the
  creator's own chapter label over the evidence gate (a description is page-supplied); it is bounded by the chapter
  and the 4-minute cap.
- **Hint fast path:** transcript lines that mention a hint term (brand/code/domain, ≥ 4 chars) are clustered (gap
  ≤ 120s) into regions that go **straight to refine** as candidates (`source: hint`); detect windows overlapping a
  region ± 60s are skipped. Regions run before any detect window.
- **Merged refine + boundaries:** the refine call also returns `first_words` / `last_words` (3–5 verbatim words at
  the ad's start and end). If each phrase occurs exactly once in the boundary context (±1 line) they are used as the
  word picks, saving the separate word pass; otherwise the labeled word pass runs as the retry. Non-English videos
  always use the labeled pass on the original track (the anchors are in the English analysis text).
- **Two tracks for non-English videos:** page.js also fetches the English auto-translation (`tlang=en` on the token
  URL). Prefilter, detect, refine, evidence and topic filter run on the English `analysisLines`; the result is mapped
  to the original track by time overlap and the word pass + snapping run on the original for exact cuts. No
  translation available → analyze the original. English videos: single track.
- Ollama `keep_alive: -1`; the model is warmed at server start.
- **Prompt input:** `Transcript language: xx`, `Video title: …` (from `videoDetails.title`), then lines formatted
  `L{i} [m:ss] text` (global line indices).
- **Ollama call:** `/api/chat`, `stream: false`, `format: <JSON schema>`, `temperature: 0`, `num_ctx: 8192`,
  `think: false` for qwen3.
- **Output schema:** `{"segments": [{start_line, end_line, category, style, brand, confidence, evidence, reason}]}`
  - category (model): `sponsor | affiliate | selfpromo | membership | crosspromo | charity | giveaway`;
    rule-based (no model call, `source: rule`): `interaction` (like/subscribe/bell/comment phrases), `intro` (no
    speech for ≥ 4s at the start), `outro` (closing phrases in the final 60s), `recap` ("previously", "coming up",
    "in this video we'll", …). Charity rule: a charity paying for the spot = sponsor; the creator's own fundraiser =
    charity.
  - style: `read | integration` (meaningful for sponsor)
- **Rubric (system prompt):**
  - sponsor = any third-party brand; a creator-specific code or link is the standard sponsor pattern, not selfpromo.
    selfpromo = only things the creator owns. Disclaimers about sponsors and the video's own subject product are
    never segments.
  - read = "sponsored by", promo codes, "link in the description", generic benefit claims, topic switch away and back.
  - integration = product used to do the video's actual task, advances the content, no hard topic break.
  - mixed (integration that ends in a promo-code pitch) → two segments; only the pitch is a read.
  - start at the transition line ("but first, a word from…"); end at the last promo line, not where content resumes.
  - transcripts may be auto-generated (no punctuation, misheard brands) and in any language; reasons in English.
- **Two passes.** Pass 1 (detect) runs the windows above; its segments are candidates only (window edges cut
  ads, line ends overshoot). Pass 2 (refine), for each `sponsor` candidate: build a window from ~90s before to
  ~90s after it and ask for the full extent of that one promotion (model may return two for mixed, or none to
  withdraw it). Then offer the words of ±1 line around each boundary line as numbered words (`S0..`, `E0..`)
  and ask for the first and last ad word as `{first: "S9", first_word: "but", last: "E28", last_word: "video"}`.
  A label that is invalid (the model once answered with global line indices) is resolved by the word text if it
  matches exactly one word in the context; the log says which rule resolved each boundary.
  `selfpromo`/`interaction` candidates are kept as-is (they're `show`).
- **Post-processing:**
  - Drop any segment whose lines fall outside the window it was given (hallucinated indices).
  - start = start of the first ad word; end = end of the last ad word − 0.3s (round inward). If the word
    pick is invalid, fall back to the boundary lines' start/end.
  - **Snap to natural pauses** (word ends are capped at their cue end, so pauses between cues show as gaps):
    start: if the sentence containing the pick begins inside the ad lines, snap backward to that sentence start
    (still ad); else forward to the nearest sentence start, else the largest gap ≥ 0.25s, within 5s and inside
    the ad lines. End: if the sentence containing the last word ends inside the ad lines, extend to it; then, if a
    pause ≥ 0.25s follows that word directly, end at the start of the pause, else keep the pick − 0.3s. **The end
    never moves past the picked last ad word into the next sentence**: a pause after a later word is not used
    (that word is content). Word times are clamped into their line (start ≤ end) before any of this.
    Original and snapped times are logged.
  - Action (server default): sponsor+read with confidence ≥ `SKIP_THRESHOLD` (0.85) → `skip`; sponsor+integration
    → `keep`; every other category → `show` (label-only). The user re-maps each category to skip / label / off in
    the popup; content.js applies it instantly. Charity never auto-skips unless the user sets it.
  - **Evidence gate (every category):** each model-labeled segment must carry an `evidence` quote found verbatim
    in its lines (±1 line); otherwise a sponsor skip is downgraded to `show` and any other segment is dropped. A
    sponsor skip's quote must additionally contain a *sponsor* cue (prefilter sponsor cues + description hints; the
    other-category cues such as patreon/merch/giveaway do not count). Chapter and rule segments are exempt (their
    evidence is the chapter title / the matched phrase). Line labels/timestamps, quotes and ellipses are stripped from the evidence
    first; a full match (≥3 words) or any verbatim run of ≥6 words passes. Otherwise → downgraded to `show`.
  - Word pass fallback is inward only: invalid pick → retry once → start = end of first ad line, end = start of
    last ad line; if < 3s remains, downgrade to `show`. Never fall back outward to a line end.
  - Merge overlapping or touching (gap ≤ 1s) segments with the same action and brand.
  - **Post-filter** (keep/show only; skips are never dropped here, only logged): drop if evidence/reason reads like
    a sponsor disclaimer; drop if the brand appears in the video title or is mentioned in ≥ 3 transcript lines
    outside the segment (it's the subject); **drop a `sponsor` keep/show that has no ad marker**; drop `show` below
    `SHOW_THRESHOLD` (0.7). Logged once, at the end.
    **Ad markers** (`AD_MARKER_RE`, `ad_markers()`): sponsorship language, a code, an offer, a link or a call to
    action, or a description hint, in the evidence quote or the segment's lines ± 1, or next to the same brand
    elsewhere in the video ("sponsored by X" at the top, X used later); or YouTube's paid-promotion flag, when it
    was received and is true (false or not received changes nothing). A creator narrating their own brand work as
    part of the story ("we're shooting for Fossil today") has none and is content, not an integration. This is a
    filter and not a prompt rule because the prompt did not hold: two wordings of a "never label" rule left
    qwen3:14b's answer unchanged (sponsor/integration, 0.90 in detect, 0.80 in refine) on that line.
  - Each segment also carries `line_start`/`line_end` (pre-refinement times) for the log and tooltip.
- Log every final segment to the terminal: action, refined time range, line-level range, category/style, brand,
  confidence, reason. Also log each detect/refine/words call with its timing, the prefilter summary, pause/resume/
  evict events, and per job: wall time, working time, Ollama calls, time-to-first-skip. Each finished job appends
  a row to `server/cache/results.local.md` (gitignored: viewing history). The curated test set with expectations
  and verdicts is `server/testset.md`.

### [8]–[9] Playback (content.js + content.css)
- After POST, poll GET every 2s until `done`/`error`. Redraw markers on each update.
- Video element: `video.html5-main-video`. Progress bar: `.ytp-progress-bar`.
- **All visuals come from the design system** (`DESIGN.md`, `extension/ui/tokens.css` + `components.css`; the
  gallery at `design/gallery.html` shows every state). `content.css` and `popup.css` only place things and hold
  what is specific to the real surfaces. Monochrome plus one accent: the accent means *live* or *skip*, nothing
  else is coloured; hierarchy is the opacity ladder; no shadows, borders or dividers.
- Markers live in their own 4px lane (`.sr-lane`) above YouTube's bar, never on it. Meaning is shape and tone:
  skip = filled accent, integration (keep) = outline, label-only (show) = dim, low confidence = hatched
  (sponsor read under 0.85, anything else under 0.8). A skip marker whose segment has been dealt with (skipped,
  undone, seeked into) is `.is-done`: the accent drains to the dim fill, because it will not skip again in this
  page view. Hover shows a glass tooltip with name, chip, confidence, time, what will happen (will skip / skipped /
  plays), and the evidence quote.
  Redraw on `loadedmetadata`.
- On `timeupdate`: if inside a `skip` segment (before `end - 0.5`) not already handled → mark handled,
  set `video.currentTime = end`, show the toast for 6s: name, chip, "m:ss skipped", a hairline with the skipped
  span, the evidence quote, **Undo** and **Wrong skip**.
- Undo restores the pre-skip time; the segment stays handled. **Wrong skip** (next to Undo) undoes and POSTs a
  `false_skip` report. The popup's **Missed an ad here** POSTs a `missed_ad` report at the current playhead.
- Manual seek into a skip segment (`seeking` not caused by us) → mark it handled; respect the user.
- Do nothing while `#movie_player` has class `ad-showing` (YouTube's own ads share the video element).
- Status badge bottom-right (glass pill, state dot, mono count; collapses to the dot after 3s): reading captions /
  analyzing 2/4 / ready · N to skip / nothing to skip / no ads / no captions / server offline / analysis failed.
  Shown only in **dev mode** (popup toggle); dev mode also gates ordinary console logs (errors always print).
- **Settings** (`chrome.storage.local.settings`, edited by the popup, applied instantly by content.js without
  re-analysis): `enabled` (off = no analysis, no markers), `actions.sponsor_read` skip|show,
  `actions.selfpromo` / `actions.interaction` skip|show|off (off = no marker), `devMode`, `allowlist`
  {channelId: name} (markers still show, nothing skips). The server's action stays in the tooltip when overridden.
  `chrome.storage.local.stats` holds, for today and all-time: skips and seconds saved (an undo takes its skip back
  and counts as `undos`), and `kept` (integrations the playhead passed through, once per page view). The popup
  leads with the all-time time saved; `getState` gives it the video's duration and each segment's outcome (`done`).

## Build stages

Each stage ends with a "done when" check on a real video.

1. **Extension skeleton + video detection** — manifest, content.js logs `[SecondRead] video <id>` on load and on
   every in-app navigation, tears down cleanly.
   *Done when:* clicking through 3 videos logs 3 correct IDs, no duplicates.
2. **Caption fetch + parse** — page.js (paths A and B), content.js requests captions and logs line count, language,
   track kind, path used, and the first 5 lines.
   *Done when:* works on a manual-caption video, an auto-caption video, after in-app navigation, and reports
   `no captions` on a video without any.
3. **Server skeleton + relay** — server.py with the API above and a **stub classifier** (fake segment), background.js
   relay, content.js POST + polling.
   *Done when:* opening a video shows the stub segment in the console and in `cache/<id>.json`.
4. **Qwen classification** — real Ollama call, prompt, schema, windows, first-window-first.
   *Done when:* a known sponsored video returns a correct sponsor read with sane boundaries in the server log.
5. **Post-processing + cache** — hallucination filter, boundary snapping, actions, merge, transcript-hash cache.
   *Done when:* revisiting a video is instant and segment times line up with the actual read (±3s).
6. **Playback UI** — markers, skip, toast with Undo, manual-seek respect, ad-showing guard, status badge.
   *Done when:* the read is skipped live, Undo works, seeking back into it lets it play, integrations stay green.
7. **Tuning pass** — collect ~20 real videos (reads, integrations, mixed, non-English, no sponsor), log results,
   tune prompt and threshold until wrong skips are ~zero.
